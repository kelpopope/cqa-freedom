# UI-аудит интерфейса CQA

Проверка по скиллу **ui-ux-pro-max** (nextlevelbuilder, MIT; 10 категорий, 119 правил UX, чек-лист перед сдачей) и по устройству зрелых продуктов контроля качества: Zendesk QA (бывший Klaus), MaestroQA, Observe.AI, Intercom.

## Что взято у рынка
| Продукт | Приём | У нас |
|---|---|---|
| Zendesk QA | Разговор рядом с панелью оценки; N/A не влияет на балл; в споре (dispute) оператор может предложить свой ответ, комментарий обязателен | Три колонки «очередь, диалог, оценка»; N/A с перераспределением; в апелляции — необязательный «предлагаемый ответ» |
| Observe.AI | Плеер и карточка оценки на одном экране; «моменты» на таймкодах | Плеер звонка с отметками нарушений; карта разговора с проблемными репликами |
| MaestroQA | Взвешенная рубрика, «авто-провал» отдельно от баллов | Веса чек-листа, грубые нарушения флагом отдельно от итога |
| Intercom | Очередь слева, переход между диалогами без возврата к списку | Очередь + клавиши J / K |

## Найдено и исправлено
| # | Правило скилла | Было | Стало |
|---|---|---|---|
| 1 | `content-priority`, `progressive-disclosure` | Итог, резюме и два блока уведомлений занимали весь первый экран, критерии — ниже | Компактный итог, уведомления в одну строку, длинное резюме сворачивается («Читать полностью»), всё прокручивается вместе: критерии видны сразу |
| 2 | `color-contrast` (4.5:1) | Третичный текст 3.9:1 | `#687066`: ≈5:1 на белом, ≥4.5:1 на светлых плашках |
| 3 | `whitespace-balance` | Грубое нарушение показано четырьмя способами | Бейдж в итоге + одна строка-флаг + строка критерия 08 |
| 4 | `primary-action` | Две главные кнопки на экране | «Оценить все» — второстепенная, главная одна: «Подтвердить проверку» |
| 5 | `aria-labels`, `nav-label-icon` | В свёрнутом меню иконки без доступного имени | `aria-label` у пунктов меню |
| 6 | `skip-links`, `focus-on-route-change` | Нет | Ссылка «Перейти к содержимому», фокус в контент после смены экрана |
| 7 | `touch-target-size`, `readable-font-size` | Кнопки 32 px, поля 13–14 px на телефоне | На сенсорных экранах цели ≥44 px, поля 16 px (без автозума iOS) |
| 8 | `loading-states` | Переключение диалога без обратной связи | Колонки приглушаются, `aria-busy`, ошибка — тостом |
| 9 | `input-labels` | Поле group_id без видимой подписи | Подпись «Набор» |
| 10 | `truncation-strategy` | Обрезанный заголовок в очереди без полного текста | Полный текст во всплывающей подсказке |
| 11 | `cursor-pointer` | Не на всех кликабельных элементах | Глобально для кнопок, ссылок, подписей полей |
| 12 | Вёрстка | При переносе кнопок шапки страница начинала прокручиваться | Рабочее место занимает ровно оставшуюся высоту |

## Что сознательно не взято
Автоподбор дизайн-системы скилла предложил тёмную OLED-тему, тёмно-синюю палитру, Fira Code и структуру лендинга «Enterprise Gateway». Это противоречит бренду Freedom и требованию организаторов о корпоративном стиле, поэтому не применено (скилл сам требует проверять соответствие продукту).

## Чек-лист перед сдачей
- [x] SVG-иконки одного набора, без эмодзи
- [x] Указатель-рука на кликабельных элементах
- [x] Контраст текста ≥ 4.5:1 в светлой теме
- [x] Видимый фокус, работа с клавиатуры, ссылка «к содержимому»
- [x] `prefers-reduced-motion`
- [x] Бейджи и статусы — текстом, не только цветом
- [x] Ширины 390, 768, 1024, 1440: без горизонтальной прокрутки
